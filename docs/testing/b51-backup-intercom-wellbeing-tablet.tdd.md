# B5.1 backup, intercom and wellbeing tablet acceptance

This independent Client slice retains the `18/125` queue and `0/63` selected
feature counters. It closes three tablet UI acceptance areas without claiming
physical Huawei MatePad, DeX, Home Assistant door hardware, native health
provider, or system file-picker acceptance.

1. **Encrypted backup and restore:** export, file selection, decrypt and apply
   stay inside the shared tablet surface and grouped settings language. Primary
   actions are at least 48 dp, keyboard reachable, and announce results through
   a live region. A retained action cannot capture data after the exact home,
   PIN, window, route, interaction, or lifecycle authority expires.
2. **Intercom home:** connection evidence, empty/error/loading states and door
   station cards share the tablet hierarchy. Retry, configure and door-release
   controls expose 48 dp keyboard and TalkBack targets. Root callbacks and door
   confirmation are bound to the exact Home Assistant account, visible route,
   interaction epoch and foreground lifecycle before any navigation or write.
3. **Private wellbeing:** readings and source configuration use the same shared
   surface and section grammar. The explicit read action is 48 dp, keyboard and
   TalkBack reachable in English and Turkish at 600/1200 logical pixels with 2x
   text. Its captured access session and controller must still match before a
   health query; late private-session callbacks remain fail closed.

The RED tests demonstrated an export action bypassing its route gate, an
unbound intercom retry callback, and a readings view without the shared section
or 48 dp action contract. The focused GREEN suites exercise those regressions
alongside existing restore, door release, PIN/privacy, account, route,
background and idle boundaries.
