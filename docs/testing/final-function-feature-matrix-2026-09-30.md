# FINAL.FUNCTION production capability matrix — 30 September 2026

This matrix records the path that a user can actually enter, the normal
Core/provider or native runtime that path reaches, and the evidence that exists
for that path. A test file being present is not an acceptance result. `Wired`
means that the normal product composition has a concrete implementation;
`Partial/open` names a known dead or unshipped part. Physical devices, accounts,
models, radio delivery and exact-HEAD CI remain separate evidence gates.

The deployment references below use the normal `create_configured_app` entry
point, the immutable Server image, and the optional Linux host-worker package.
Injected providers used only by tests are not counted as production wiring.
The shared host IPC is mounted read/write into Core at `/run/larenor-workers`;
it is deliberately outside Core's private `0700` data directory. Dedicated
workers currently use UID 10003 (AI), 10004 (mesh), 10005 (Proxmox), 10006
(NUT) and 10008 (Keenetic), with Core UID 10001 and IPC GID 10002.

## Production blocker reconciliation

The previously recorded F15/F16, F18 and F55 packaging blockers are resolved in
the normal unified composition. Their sockets now share the dedicated host IPC
tree and appear inside Core only at `/run/larenor-workers`; none relies on the
private Core data directory. Keenetic command execution likewise has a packaged
UID 10008 worker with a private policy/key, kernel peer checks and the same IPC
mount. These are implementation-complete paths awaiting their stated
exact-head/hosted-Linux and physical-provider gates, not missing composition.

F45's durable Frigate→F54 private notification handoff is committed at
`cc01d968f5a57387cfb3781b17a8237b7c357104`: restart/lost-ACK dedupe and
transaction-current source/session/camera authority passed the named focused
acceptance. It is awaiting broad CI; physical delivery remains manual. The feature matrix remains an inventory; it does
not award acceptance merely because a test file exists.

One F01–F21 implementation blocker remains: F11 still needs an actual
CPU/memory-isolated runtime after removing its unsupported hard-limit claims. F12 now implements the required
2025-06-18 [lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle)
notification and the bounded
[transport](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
boundary. Its custom bearer grant remains deliberately outside the standard
[authorization discovery](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)
flow, so the product does not claim OAuth interoperability. That explicit
credential limitation is distinct from a dead or dummy production route.
