# B5.1 Keenetic root, Wi-Fi and port tablet acceptance

This independent slice covers the three related direct-Keenetic routes that
were absent from the open B5.1 entity/device, metric, media, settings and
operations branches. It does not change the device or metric files owned by
those branches.

## Three accepted criteria

1. **One tablet hierarchy.** The router root, Wi-Fi radios and read-only port
   rules use the shared large-title service shell and grouped settings rows.
   English and Turkish at 600 and 1200 logical pixels with 200% text preserve
   48 dp content actions, keyboard Enter activation, headings and TalkBack
   names. The existing explicit Wi-Fi confirmation remains keyboard
   cancellable and is never bypassed.
2. **Truthful state and evidence.** Wi-Fi and port routes announce loading,
   empty and failure as separate live regions; private provider errors never
   enter copy. All three populated routes show the passive Keenetic connection
   evidence, keeping locally saved configuration, reachable transport and a
   verified domain read separate. A failed read is not presented as an empty
   router result.
3. **Exact authority.** Refresh, navigation and Wi-Fi changes retain the
   existing direct-home, account, provider identity, interaction epoch, route,
   visibility and app-lifecycle checks. Captured actions fail closed after any
   authority change. Late refresh completion cannot publish into a later
   session, retry a command or navigate under a replacement account.
