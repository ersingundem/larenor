# B5.1 authentication, inventory and ARR tablet acceptance

This slice accepts three remaining Client surfaces without changing their
service ownership or advancing the selected feature backlog. Queue progress
remains `18/125`; selected-feature progress remains `0/63`.

1. **Home Assistant setup:** The first-run URL/token form and discovered-server
   choices use the shared tablet surface, grouped settings hierarchy and 48 dp
   actions. Password-manager/keyboard Done invokes the same validated action as
   Connect. A captured action, discovery result, verification response or
   navigation result cannot survive background, covered-route, inactive
   interaction or lifecycle authority changes; the token draft is retired.
2. **Core inventory:** Manual QR entry, Open, Scan and resolved-item actions use
   the shared surface and settings/action language with 48 dp keyboard and
   TalkBack targets. Compact and wide tablet layouts retain their verified
   read-only detail split. Core/home/session authority remains owned by the
   existing controller and route; late or foreign results are discarded.
3. **ARR add:** Radarr, Sonarr, Lidarr and Readarr search/add flows use the same
   surface, 48 dp search field and keyboard-reachable result actions. Loading
   and failure feedback is announced. Account, provider, route, idle and
   lifecycle drift still invalidates lookup, picker and confirmation callbacks,
   and uncertain writes remain blocked from replay.

The focused matrix covers English and Turkish at 600 and 1200 logical pixels
with 2x text, keyboard activation and TalkBack semantics. Existing route,
inventory authority and ARR session suites provide exact stale-callback and
single-write evidence.
