# F62 SAF client grant boundary — 2026-10-03

## Scope

This slice prepares an Android Storage Access Framework tree grant for one exact
RDP profile. It does **not** enable RDP file redirection. The existing public
`files` capability and every session request remain `false` until the separate
mirror, drain, and explicit save journal is implemented and accepted.

The profile settings record moved from version 2 to version 3. Version 1 and 2
records still decode with no file grant. Version 3 stores only an opaque native
grant id and its monotonic revision. A provider URI, display name, path, file
name, or document contents never cross the MethodChannel or enter Dart secure
storage.

## Authority and wire boundary

The new SAF calls alone use schema 5. Existing RDP session and microphone calls
remain schema 4 in this stage. Every select, prepare, activate, observe, and
retire operation carries this closed authority object:

```text
{schemaVersion: 5, namespaceDigest: 64hex,
 profileRef: 64hex, profileRevision: JS-safe positive integer}
```

Native and Dart independently derive `authorityId` as SHA-256 over UTF-8
`larenor-rdp-saf-authority-v1`, NUL, namespace digest, NUL, profile ref, NUL,
and the decimal profile revision. Native never trusts a caller supplied
authority id. Receipts return only the derived authority id, opaque 32-hex
grant id, revision, and a closed state.

The picker produces `prepared`. Dart first saves that opaque receipt to the
profile-bound encrypted settings record, then asks native to activate it. A
lost activation acknowledgement is reconciled with the read-only observation;
the picker is never reopened automatically. Replacement requires an explicit
retirement receipt and removal of the old settings reference before another
selection.

Native retirement is durable and idempotent. It records the exact authority,
grant, expected revision, and request tombstone before releasing the persisted
URI permission. An incomplete release remains `unknown`; Dart retains the
opaque reference for a later observation and does not claim retirement.

## Picker lifecycle

`ACTION_OPEN_DOCUMENT_TREE` opens a separate Android activity. The one exact
owned picker may therefore survive `inactive`, `hidden`, `paused`, focus loss,
and the corresponding `onStop` while its bounded request is pending. Its result
is not consumed until the original route and profile authority are current and
Larenor is resumed and focused again. Route, account, PIN, profile, settings,
dispose, explicit cancel, and deadline retirement still cancel the exact native
request. A stale callback cannot open RDP, activate a grant, or revive a
successor profile.

The UI says that the folder permission is prepared and that file sharing is not
enabled. It exposes no file browser or transfer control in this stage.

## Verification and remaining boundary

Focused tests cover strict settings migration, authority derivation, exact
MethodChannel shapes, raw-field rejection, post-result authority loss,
picker pause/focus handoff, route cancellation, prepare-before-activate, explicit
retire-before-remove, and `files == false` on the subsequent RDP request.

The next slice must add a private app-owned mirror, bounded per-file and total
limits, a durable transfer/save journal, exact close/drain evidence from
FreeRDP, and explicit SAF write/readback. No file transfer capability may be
advertised before that end-to-end path and its disposable owned-provider gate
pass.
